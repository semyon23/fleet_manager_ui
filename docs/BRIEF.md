## 1. Цель проекта

**Что понял из твоих сообщений:**
Веб-интерфейс (fleet manager) для управления парком промышленных мобильных роботов AMR/AGV. Ты пишешь бэкенд, мне отдаёшь фронт: визуал, меню, вкладки, работу с картами и роботами в реальном времени.

## 3. Функциональные разделы (sidebar)

### 3.1 Dashboard (главная)
- Счётчики: онлайн / в зарядке / простой / ошибка / offline  : да 
- KPI: пройденный километраж, выполненные миссии, uptime парка : да, по каждому роботу (моточасы, км)
- Лента событий (real-time) : можно
- Мини-карта с превью текущей обстановки

### 3.2 Live Map (карта в реалтайме)
- План помещения как подложка  
- Роботы как маркеры с направлением, цветом по статусу
- Клик на робота → сайдбар с деталями (батарея, задача, лог) : да
- Фильтры: показать только по статусу / группе / зоне
- Zoom / pan / центрирование на выбранном роботе : да

### 3.3 Map Editor (редактор карт)
- Загрузка подложки (PNG/SVG плана цеха или .pgm из ROS) : .pgm из ROS  
- Инструменты рисования: walkable-зоны, forbidden-зоны, зоны зарядки, парковки : интегрируй vda5050-lif-editor 
- Waypoints (точки) и маршруты (ребра между ними)
- Точки погрузки/разгрузки со свойствами
- Версионирование карт (история изменений, откат)



### 3.4 Robots (управление роботами)
- Таблица: ID, модель, статус, батарея, задача, uptime, последняя связь : да 
- Карточка робота: детали, лог, ошибки, ручные команды (стоп/пауза/на базу) : да
- Группы роботов, теги 

### 3.5 Missions / Tasks
- Очередь текущих задач   : это не задача UI (только отображение)
- Планировщик (создать миссию: откуда → куда → приоритет → расписание) это не задача UI (только отображение)
- История выполнения : это не задача UI (только отображение)
- Шаблоны миссий : это не задача UI (только отображение)

### 3.6 Alerts / Notifications
- Список активных алертов (коллизии, low battery, потеря связи, застревание) : (только отображение)
- Настройка правил (при каком событии слать пуш / письмо / в Телеграм) : (только отображение)

### 3.7 Analytics
- Графики: загруженность роботов, тепловая карта путей, время простоя : нет 
- Экспорт отчётов (CSV/PDF) : нет

### 3.8 Settings
- Пользователи и роли
- Интеграции (WebSocket/MQTT endpoints, SSO) : предроставь endpoints для fleet control, WebSocket -> fleet ui
- Общие настройки (единицы, часовой пояс, тема)

## 4. Работа с картами (детали)

**Наше предложение:**
- Формат подложки: PNG или SVG (позже — .pgm/YAML из ROS `map_server`)
- Редактор на **react-flow** (waypoints + рёбра) поверх canvas-подложки, ИЛИ **Konva.js** если нужно много кастомной геометрии
- Координаты хранятся в метрах, конвертация px↔м по калибровке подложки

**Вопросы:**
- В каком формате ты будешь отдавать карту с бэка? (JSON со списком зон/точек? .pgm+.yaml как в ROS?) : карта с робота загрузится на сервер карт, потом в ui для редактирования и обратно на сервер
- Один робот работает на одной карте, или парк может обслуживать несколько зон/этажей? много карт, много роботов, назначаем роботов на картах, 
- Нужна ли поддержка мульти-этажности (переходы между картами)? да
